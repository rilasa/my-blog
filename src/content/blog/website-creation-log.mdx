    # Astro Reimu：修复 Tab 切换时文章目录异常

## 一、问题现象

在 MDX 文章中使用 `<Tabs>` 和 `<TabItem>` 组件后，出现两个问题：

1. 切换 Tab 后，文章目录可以改变，但再次切换回原来的 Tab 时，目录无法恢复。
2. 目录识别错误，显示了不属于当前 Tab 的标题。

## 二、定位问题

涉及三个文件：

- `src/components/mdx/Tabs.astro`：负责创建 Tab 标签、切换激活状态并触发事件。
- `src/components/mdx/TabItem.astro`：负责包裹每个 Tab 的内容。
- `src/components/sidebar/SidebarScript.astro`：负责筛选目录、重建目录树和绑定滚动监听。

### 1. Tab 的 HTML 结构

`TabItem.astro` 的核心代码：

```astro
<div class="tab-pane" data-tab-title={title}>
  <slot />
</div>
```

每个 Tab 的内容都位于 `.tab-pane` 中。当前选中的面板会添加 `.active` 类。

### 2. Tab 切换事件

`Tabs.astro` 的 `switchTab()` 函数负责切换 `.active` 类，并触发：

```js
tabs.dispatchEvent(
  new CustomEvent("tabs:change", { bubbles: true })
);
```

`SidebarScript.astro` 监听这个事件，在切换后更新目录：

```ts
function handleTabsChange() {
  updateTocForActiveTab();
  initTocScroll();
}
```

因此，Tab 切换事件本身已经具备了通知目录刷新的机制。

### 3. 根本原因：原始目录项丢失

原来的 `updateTocForActiveTab()` 直接从当前 DOM 中获取目录项：

```ts
const allItems = Array.from(
  root.querySelectorAll<HTMLLIElement>("li.toc-item"),
);
```

随后，函数会筛选目录项、移除旧的子目录结构，并重建目录树。

问题在于：不符合当前 Tab 条件的目录项会被移出 DOM。再次切换时，`querySelectorAll()` 只能找到仍然存在于 DOM 中的项目，已经移走的项目无法自动恢复。

此外，原有逻辑会保留找不到对应标题的目录项：

```ts
if (!heading) return true;
```

这可能导致目录混入不属于当前 Tab 的项目。

## 三、解决方法

### 1. 缓存完整的原始目录项

在 `SidebarScript.astro` 中，找到原有的两个变量：

```ts
let cleanupFunctions: (() => void)[] = [];
let tocCleanupFunctions: (() => void)[] = [];
```

在下面添加：

```ts
const originalTocItems = new WeakMap<
  HTMLOListElement,
  HTMLLIElement[]
>();
```

`WeakMap` 用于把每个目录列表与它最初的完整目录项集合关联起来。

### 2. 从缓存中读取目录项

将原来直接查询 DOM 的代码：

```ts
const allItems = Array.from(
  root.querySelectorAll<HTMLLIElement>("li.toc-item"),
);
```

替换为：

```ts
let allItems = originalTocItems.get(root);

if (!allItems) {
  allItems = Array.from(
    root.querySelectorAll<HTMLLIElement>("li.toc-item"),
  );

  originalTocItems.set(root, allItems);
}
```

这样，每次切换 Tab 时，都可以从完整的原始目录项集合重新筛选，而不是从上一次修改后的 DOM 中获取目录项。

### 3. 修正目录筛选规则

将原来保留找不到标题的目录项的逻辑：

```ts
if (!heading) return true;
```

改为：

```ts
if (!heading) return false;
```

完整的核心判断是：

```ts
const heading = document.getElementById(headingId);

if (!heading) return false;

const pane = heading.closest<HTMLElement>(".tab-pane");

return !pane || pane.classList.contains("active");
```

含义：

- 找不到对应标题：不显示该目录项。
- 标题位于 Tab 外部：保留。
- 标题位于 Tab 内部：只有当前激活的 Tab 才显示。

### 4. 每次重新构建目录树

筛选完成后，代码会清除旧的子目录结构，并根据 `toc-level-*` 类所表示的标题层级，重新创建 `ol.toc-child`，将目录项放回正确的位置。

因此，目录不仅能够切换，还能保留原有的标题层级结构。

## 四、验证方法

修改后，在项目根目录运行：

```bash
pnpm run build
```

然后启动开发服务器：

```bash
pnpm run dev
```

依次测试：

1. 打开第一个 Tab，检查目录。
2. 切换到第二个 Tab，检查是否只显示当前 Tab 的标题。
3. 切回第一个 Tab，确认原目录恢复。
4. 多次来回切换，确认目录保持正确。
5. 检查目录层级、滚动高亮和目录链接是否正常。

最终，两个问题均已成功解决。

## 五、本次学到的知识

- **DOM 操作**：JavaScript 可以动态移动、删除和重建 HTML 元素。
- **事件驱动**：Tab 切换后，通过自定义事件通知其他功能刷新。
- **缓存原始数据**：如果操作会破坏原始结构，应保留数据来源，避免后续无法恢复。
- **筛选与重建**：先根据当前状态筛选数据，再重建界面，比直接修改后丢弃原始数据更可靠。
- **Debug 流程**：复现问题 → 定位相关文件 → 阅读调用关系 → 修改最小范围的代码 → 本地验证。

本次修改的核心思想是：**保留完整的原始目录项，每次切换都重新筛选，再根据标题层级重建目录树。**
